# Speech therapy reward games (Phaser 3 demo)

A browser demo of the flow in the job post: the therapist shows a **speech card**, starts a **one-minute reward game**
that the student plays, then goes back to the next card. Both screens show the same game in real time.

- 4 reusable game templates: memory match, sort it, copy the pattern, odd one out.
- Content (themes, pictures, words, categories) comes from JSON packs in `content/`; one template becomes many games.
- Original vector artwork (`assets/art/*.svg`, generated by `make_art.py`) with a bright, kid-friendly style.
- Adaptive difficulty: a clean win raises the level, 3+ mistakes lower it (levels 1-3). The therapist can override it.
- Real-time sync over WebSocket (`server/relay.py`), with a same-browser fallback.
- Runs on laptops and tablets, touch friendly, sounds generated in the browser (no audio files).

## Run

```bash
./start.sh
```

Open http://localhost:8770, press "Start as therapist", then "Open student view" (or open the copied link on another
device on the same network and add `?ws=ws://<your-ip>:8766`). Tests: http://localhost:8770/tests.html (19 tests).

Needs Python 3 only. The first run creates `.venv` and installs the `websockets` package.

## How it works

| File | Role |
| --- | --- |
| `js/logic/*.js` | One pure module per template: `create`, `apply`, `isDone`. No Phaser, DOM, or timers |
| `js/authority.js` | Session state machine: cards, reward game, timers, adaptive level, role rules |
| `js/transport.js` | WebSocket transport with reconnect, plus the BroadcastChannel fallback |
| `server/relay.py` | Moves messages between a room's therapist and students, caches the latest state, reports presence |
| `js/views.js`, `js/scene.js` | Phaser rendering. Views draw state and send taps as intents, they never change state |
| `content/*.json` | Content packs. A production build would load these from the platform's API |

Sync model: the therapist side holds the one authoritative state. A student sends intents ("flip card 3", "place item 2 in
box 1"); the authority checks the role and the rules, applies the change, bumps `version`, and publishes a snapshot.
A student who joins late or reconnects gets the latest snapshot from the relay. Snapshots are ordered by `(epoch, version)`.

## Limits of this demo

- The authority runs in the therapist's browser. If that tab closes the session is lost. A production build would run
  the same `Authority` class on the server, which needs Node (the logic is plain ES modules, so it moves as it is).
- The relay has no authentication, invite tokens, TLS, rate limits, or persistence.
- On a static host (for example GitHub Pages) there is no relay, so the demo falls back to two tabs in one browser.
- Drag and drop shows the result for both players, not the live drag. Plain JavaScript here, TypeScript in production.
- Not covered: accessibility audit (colour contrast, screen readers, reduced motion), real device testing, content admin API.
